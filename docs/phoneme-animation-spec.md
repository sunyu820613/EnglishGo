# 音位发音动画视觉规范（M2 样板）

状态：待评审 | 分支：`react-rewrite` | 撰写：frontend-designer
依据：`docs/architecture-react-rewrite.md`（§5 `PhonemeAnimationRig` schema，接口已锁定，本文档不改动字段名/类型，只定义取值与视觉呈现）、`docs/design-system-react-rewrite.md`（Token 体系）、`docs/phonetics-react-rewrite-scope.md`（M2 验收标准）
范围：5 个样板音位 `/iː/ /æ/ /θ/ /r/ /ŋ/` 的正面嘴型 + 侧面口腔剖面 SVG rig 视觉设计。本文档不产出图片/代码，供 implementer 与内容制作者据此绘制 SVG 与填写关键帧数值。

---

## 设计目标

M1 已跑通"文字+音频+例词"层，M2 要解决的核心体验问题是：**孩子看不见自己嘴里发生了什么，只能靠模仿声音，无法建立"舌位/唇形/气流"这些看不见的发音动作与听到的声音之间的对应关系。** 正面嘴型动画负责"照镜子"式的直观模仿（孩子可以对着屏幕学口型），侧面口腔剖面负责"透视"式的原理讲解（家长辅助讲解时用，也满足少数孩子对"为什么舌头要这样放"的好奇心）。两个视图必须在同一份归一化关键帧数据下同步播放，不能出现"嘴型已经变了但剖面图还没动"的割裂感，这是 M2 要验证的最大技术风险。

同时验证：同一套关键帧数据能否在男声/女声、正常速/慢速四种音频变体下保持"看起来对得上"的同步观感（架构文档已标注这是近似方案，允许感知层面的可接受误差，不追求逐帧精确）。

## 1. 正面嘴型 SVG rig 控制参数清单

对应 `FrontMouthPose` 接口，全部为 `[0,1]` 归一化数值型参数（`tonguePeek` 除外单独说明），语义如下：

| 参数 | 视觉含义 | 0 值状态 | 1 值状态 |
|---|---|---|---|
| `jawOpen` | 下颌开合度，驱动下唇整体下移量 | 上下唇几乎闭合（静止状态） | 下颌张到自然发音的最大幅度（不做夸张到解剖极限，参考正常说话张口上限） |
| `lipRound` | 圆唇度，驱动上下唇宽度收窄+唇形趋圆 | 唇形自然宽度，不收拢 | 明显嘟起的圆唇（如发 /uː/ /w/ 的程度，本批 5 音位最高只到 `/r/` 的 0.5） |
| `lipSpread` | 唇部横向展开度，与 `lipRound` 是两个独立轴（可同时非零表达"既不圆也不完全放松"的中间态，但设计上二者很少同时取高值） | 唇角不主动横拉 | 嘴角明显向两侧拉开展平（如发 /iː/） |
| `lipCompression` | 唇部闭合压紧程度，本批样板音位中数值都很低，主要为塞音（/p/ /b/ 等，M3 用）预留 | 唇不施加压紧力 | 双唇完全压紧闭合（本批不用到 1） |
| `cornerPull` | 嘴角上扬/后拉的表情化修饰，用于让口型动画带一点"笑意"而非死板机械口型，避免"解剖图感" | 嘴角中性 | 嘴角明显上扬后拉 |
| `teethVisible` | 上排/下排牙齿可见度（露齿程度），驱动牙齿 SVG 层的 `opacity`/裁切范围 | 完全不露齿 | 上下齿列清晰可见 |
| `tonguePeek` | 舌尖从唇间探出的可见度，仅用于齿间音（/θ/ /ð/），驱动舌尖 SVG 图形从唇缝间"伸出"的长度比例 | 舌尖完全不可见 | 舌尖清晰探出唇间（发 /θ/ 的典型可见程度） |

**实现要求**：`jawOpen` 是主驱动参数，唇形其余参数（`lipRound`/`lipSpread`/`lipCompression`）在 SVG 层面应设计为可与 `jawOpen` 联动形变（例如下颌张开时唇部形状会跟随拉伸），而不是各参数独立控制互不关联的图层，否则会出现"下巴张开但嘴唇形状僵硬不合理"的穿模感。implementer 可用简单的 SVG path `d` 属性插值或 `transform: scaleY`/贝塞尔控制点位移实现，不需要引入专门骨骼动画库。

## 2. 侧面口腔剖面 SVG rig 控制参数清单

对应 `SideProfilePose` 接口。侧面视图统一朝向：**面部朝右**（鼻子在右、喉咙在左），舌头分三段独立控制（舌尖/舌面/舌根），符合语音学教学惯例朝向，也让"气流从右侧唇齿流出"的方向直觉上更自然（阅读顺序从左到右，气流也从左至右流向出口）。

| 参数 | 视觉含义 | 0 值状态 | 1 值状态 |
|---|---|---|---|
| `jawOpen` | 与正面视图同义，驱动侧面下颌轮廓线下移，两个视图共用同一数值（关键帧里通常写同一个数） | 闭合 | 最大张口幅度 |
| `tongueTipHeight` | 舌尖离下齿龈的垂直高度 | 舌尖贴近口腔底部 | 舌尖抬升接近上齿龈/硬腭前部 |
| `tongueTipAdvance` | 舌尖前后位置 | 舌尖靠后（口腔中部） | 舌尖靠前（贴近或探出上下齿之间） |
| `tongueBodyHeight` | 舌面（舌身中段）高度 | 舌面低平 | 舌面明显隆起接近硬腭 |
| `tongueBodyAdvance` | 舌面前后位置 | 舌面靠后 | 舌面靠前 |
| `tongueRootHeight` | 舌根高度，仅在软腭音（/k/ /g/ /ŋ/，本批用到 `/ŋ/`）时取高值 | 舌根松弛靠下 | 舌根明显抬升接触/逼近软腭，形成口腔后部闭塞 |
| `velumOpen` | 软腭开合，即"鼻腔通道是否打开" | 软腭上抬贴住咽壁，鼻腔通道关闭（口腔音） | 软腭下垂，鼻腔通道打开（鼻音专用，本批仅 `/ŋ/` 取 1） |
| `lipRound` | 与正面视图共用同一数值，侧面视图上表现为唇部轮廓线在最右端的突出/收拢程度 | 唇轮廓平直 | 唇部明显前突圆拢 |
| `airflow` | 气流可视化模式，三态而非连续值 | — | 见下方专门说明 |
| `voicing` | 声带振动指示，布尔值 | 静止（清音） | 振动（浊音） |

**声带振动指示的视觉方案**：侧面剖面图在喉部位置（图形最左端，气管顶部）画一个小型"声带示意图标"（两条简化声带线），`voicing=true` 时该图标播放持续的小幅波纹脉动动画（振幅小、频率与 `--duration-idle`(2400ms) 量级同步循环，视觉上是"轻轻颤动"而非夸张抖动）；`voicing=false` 时图标保持静止，颜色也从"激活态"（`--color-focus`）降为"未激活态"（`--color-text-soft` 低饱和描边），双重编码（动 vs 静 + 色彩深浅）保证色弱用户也能分辨，不单纯依赖颜色。

**气流方向与强度可视化方案**：在口腔前方（唇齿出口处）画 2-3 条短弧线/波浪线作为气流指示符，随 `airflow` 状态切换呈现方式，且这些弧线的动画同样遵循 `prefers-reduced-motion`：
- `airflow: 'none'`（元音、近音等无可闻摩擦的音）：不显示气流线，或仅显示一条极淡的静态短弧线暗示"有气息但不聚焦表现"，避免元音也画出"嘶嘶风"的错误暗示。
- `airflow: 'continuous'`（擦音、鼻音）：显示 2-3 条连续波浪线，沿气流方向（口腔出口为 `/θ/`，鼻梁上方鼻孔位置为 `/ŋ/`）持续向外扩散淡出的循环动画，波浪线的疏密/振幅可用一个内部强度系数表达"气流感"，但对外只暴露 `'continuous'` 一个状态，不新增额外参数（保持 schema 精简，符合架构"不引入本阶段用不上的复杂度"原则）。
- `airflow: 'burst'`（塞音，本批 5 音位不使用，为 M3 预留）：显示一次性的短促扩散小圆点/短弧线，播放一次不循环。

## 4. 音画同步的最简可行状态机

沿用架构文档已锁定的"归一化时间轴 + 关键帧插值"机制，不引入 Azure Viseme 级别的精细时间戳方案。M2 阶段每个音位 rig 只需 **4 个关键帧**，覆盖 idle → onset → sustain → release 四态：

```
t=0.00  onset   前后一致：从静止状态快速过渡到 70% 目标姿态
                （录音已裁剪掉首尾静音，t=0 即声音开始的瞬间，
                 此时口腔动作应已接近到位，符合真实发音时构音先于/同步于发声的生理规律）
t=0.15  sustain-in  100% 目标姿态（本文档第 3 节给出的稳定值），
                声带振动/气流指示从此帧起激活
t=0.85  sustain-out 仍为 100% 目标姿态（4 个音位中除 /θ/ 外均为可持续音，
                sustain 区间应占满 t=0.15~0.85 的绝大部分时长，
                这是"看得懂"的关键——孩子需要有足够长的静止观察窗口看清口型，
                不能整个动画都在快速变化）
t=1.00  release 目标姿态回落到 90%（轻微自然收尾，不完全归零，
                避免声音刚结束嘴型就"跳变"回静止显得生硬）
```

`voicing`/`airflow` 两个非连续参数在 `t=0.15` 关键帧设为目标值、其余帧沿用最近关键帧值（按架构文档已定义的插值规则），不需要在 4 个关键帧里都重复声明，只需在状态改变的那一帧写入。

**播放结束后的收尾（rig 时间轴之外，UI 层负责）**：音频播放完毕（`ended` 事件）后，不属于 `PhonemeAnimationRig` 数据范畴，而是由承载 SVG 的组件用一次性 CSS 过渡把姿态从 `t=1` 状态过渡回全局统一的"静止待机口型"（所有参数为 0 的中性闭唇状态），时长复用 `--duration-standard`(320ms) + `--ease-standard`，不需要为此单独定义新的动效 token。这样"rig 关键帧数据"与"播放结束后的 UI 收尾动效"职责分离，rig 数据本身保持单纯（只描述发音过程），符合架构给的"接口锁定、不推翻整体方案"要求。

**慢速版本处理**：沿用架构文档"等比例时间拉伸"假设，慢速音频只是让同一组 `t∈[0,1]` 关键帧插值耗时更长，rig 数据不需要为慢速版本单独准备一份。`/θ/` 作为擦音在慢速播放时的气流线循环动画节奏也会自然被拉长（因为循环周期基于插值进度而非独立计时器），观感上是合理的（慢读时确实能感觉到气流更绵长），不需要特殊处理。

## 5. 视觉风格要求

### 5.1 画风方向判断

**正面嘴型：拟人卡通化的嘴唇/舌头**，延续既有主题吉祥物的"精品绘本感"插画气质（圆润造型、统一描边粗细 `--stroke-width`、软陶土配色），画成"一张简化的嘴部特写插画"，而不是医学教材式的解剖标注图。理由：正面视图是孩子对着屏幕模仿的"镜子"，需要有亲和力，参照六主题吉祥物已建立的视觉语言，让嘴型动画感觉像是"绘本角色在示范发音"，如果画成写实唇齿解剖图，会显得冰冷且与全书插画风格割裂，违反"反 AI 模板感"清单第 7 条"禁止插画/图标风格混搭"。

**侧面口腔剖面：简化示意图，但保持绘本化的圆润笔触，不做医学写实解剖图**。理由：侧面剖面天生是"孩子平时看不到、没有直觉经验"的内容，无法用"像不像真实器官"来评判像不像，此时最大的风险反而是画得太写实吓到低龄儿童（口腔黏膜、血管质感等细节完全没有必要）或者相反画成生硬的"教科书线框图"显得突兀廉价。设计判断：用与正面视图**同一套描边粗细、同一套配色 token、同一种圆角语言**画一个"卡通化的口腔侧切示意图"——舌头是一个软陶土质感的圆润色块，软腭是一片小圆弧，声带是两条简笔线条，让侧面图看起来像是"从同一本绘本里裁出来的教学插页"，而不是外部贴进来的医学图表。这样两个视图并排出现时观感统一，不会有"一半可爱一半吓人"的割裂感，也规避了"不准确的 AI 解剖图"风险——因为造型本来就不追求解剖精确度，是象征性示意，无需自证"医学准确"，只需在相对位置关系上准确对应第 1-2 节参数语义（舌位高低前后、软腭开合）。

### 5.2 配色方案（全部取自现有主题 token，不新增颜色）

| 部位 | 颜色 token | 说明 |
|---|---|---|
| 嘴唇轮廓/唇形 | `--color-accent` | 与主操作强调色一致，让嘴唇成为画面视觉焦点 |
| 牙齿 | `--color-surface` 填充 + `--color-outline` 描边 | 与卡片留白色系呼应，保持干净不突兀 |
| 舌头（正面+侧面统一） | `--color-primary` | 主色，确保舌头在两个视图中都是仅次于嘴唇的第二视觉焦点，前后一致便于孩子对应认知"这两张图里的舌头是同一个东西" |
| 软腭 | `--color-secondary` | 次要色，与舌头区分开但不抢视觉焦点 |
| 声带指示图标 | 激活态 `--color-focus`；静止态 `--color-text-soft` | 复用既有焦点色语义（"有事情正在发生"），双重编码见第 2 节 |
| 气流指示线 | `--color-accent` 低不透明度（用 `color-mix()` 调至约 40%） | 与嘴唇同色系但弱化，避免与嘴唇本体抢视觉权重，同时保持"同一套暖色语言" |
| 剖面图外轮廓（头部侧影） | `--color-outline` 描边 + `--color-surface-alt` 填充 | 作为背景容器色，让舌头/软腭等内部结构在其上清晰浮现 |

深浅主题下以上 token 会自动跟随主题切换（沿用 §1.4 阴影同款 `color-mix()` 机制），rig 组件不需要为六主题写六套颜色分支。

## 6. 最小对立音对比 UI 布局（通用组件，供 `/iː` vs `/ɪ/` 等复用）

### 6.1 布局结构

在音位详情页"对立音对区"内，采用左右对称双栏卡片，中间以一条竖直分隔线 + 居中的"vs"标记连接，整体作为一个独立组件（可命名 `MinimalPairComparison`，implementer 阶段定名）：

```
┌─────────────────────┐   ┌─┐   ┌─────────────────────┐
│   IPA 符号（本音位）  │   │v│   │   IPA 符号（对比音位） │
│   正面嘴型动画画布     │   │s│   │   正面嘴型动画画布     │
│   SoundButton(播放)   │   └─┘   │   SoundButton(播放)   │
│   例词（Andika 字体）  │         │   例词（Andika 字体）  │
└─────────────────────┘         └─────────────────────┘
        └──────────── 「同时播放对比」按钮（居中，次级视觉权重）────────────┘
```

- 每栏卡片视觉规范同 §4.2 通用卡片（`--radius-md` 圆角、`--shadow-rest`），不单独设计新卡片样式。
- **只放正面嘴型动画，不放侧面剖面**——对比场景的核心诉求是"孩子能看懂两个音口型有什么不同"，侧面剖面的专业性反而分散注意力，剖面对比留在各自音位详情页里单独看，不在对比组件里重复摆放。
- 例词文本用 `--font-teaching`(Andika)，与音位详情页例词区一致。
- 中间"vs"标记：一个简单的圆形徽标（`--radius-full`），底色 `--color-surface-alt`，文字用 `--font-body` 小号大写"VS"，不使用对抗性图形语言（如闪电/拳头图标），保持温和。

### 6.2 核心交互

- 单栏 SoundButton 独立可点，播放各自音位的标准发音（沿用 §4.3 音频播放控件规范）。
- 底部「同时播放对比」按钮：点击后依次播放左栏音频 → 短暂间隔（约 400ms，复用 `--duration-page` 量级） → 播放右栏音频，两个正面嘴型动画分别在各自播放窗口内同步动起来（不是同时播放两段音频叠加，遵循 `AudioService` 单语音通道打断规则，天然保证不会有声音叠加）。
- 两栏嘴型动画默认都处于静止待机口型，只有各自对应音频播放时才激活动画，互不干扰。

### 6.3 响应式

- 手机（`<768px`）：双栏纵向堆叠（上下排列而非左右挤压变形），中间"vs"徽标居中显示在两栏之间的窄条上，「同时播放对比」按钮贯穿宽度置于底部。
- 平板/桌面（`≥768px`）：维持左右并排双栏，卡片间距 `--space-lg`，"vs"徽标垂直居中于分隔线上。

## 状态设计

- **空状态**：M2 阶段仅 5 个音位有完整 rig 数据，其余音位详情页的动画区维持 M1 已定义的"动画即将上线"占位（本文档不改变该规则，只是这 5 个音位不再触发该占位）。
- **加载中**：音频请求中 SoundButton 显示小型 loading 指示（沿用 §4.3 已有规则）；SVG rig 本身是矢量图形随组件挂载即可渲染，不存在"动画资源加载中"的额外状态，无需设计骨架屏。
- **错误状态**：若某音位缺少某个声线/速度组合的音频（M2 阶段矩阵未必四种全齐），对应播放按钮走 disabled 灰态 + tooltip"暂无此声线"（沿用架构文档音频缺失优先级规则）；rig 数据缺失属于内容制作阶度问题，不应作为运行时错误处理——若某音位在 `phonemes.ts` 中 `animationRig` 字段为 `undefined`，UI 直接回退到 M1 的"动画即将上线"占位，不报错、不留白洞。
- **同步中/冲突状态**：不适用（本项目无云同步/多端账户，同前序文档结论）。

## 给 implementer 的实现要求

1. `FrontMouthPose`/`SideProfilePose`/`PhonemeAnimationRig` 三个接口字段与类型严格沿用 `docs/architecture-react-rewrite.md` 第 5 节原文，本文档只补充取值范围与视觉语义，不得新增/删减/重命名字段；若实现中确实需要新参数（如未来发现某音位无法用现有参数表达），必须先回到 architect 评审再改接口，不能自行在组件内加“影子参数”。
2. 4 个关键帧（`t=0/0.15/0.85/1`）是 M2 的固定基线，5 个样板音位一律采用相同关键帧时间点，只有各字段目标值不同，不允许为某个音位单独设计关键帧数量，保持数据结构统一以便未来批量生产 M3 剩余 42 个音位。
3. 播放结束后的"回到静止待机口型"是 UI 层职责，不得混入 `PhonemeAnimationRig` 数据（不要为此新增 `t>1` 的关键帧），复用 `--duration-standard` + `--ease-standard`。
4. 正面/侧面两个视图的 `jawOpen`/`lipRound` 在同一帧必须取同一数值（本文档第 3 节表格已保证这一点），组件实现时建议从同一份 pose 对象里派生两个视图的渲染输入，避免手工分别维护导致数值漂移不同步。
5. 颜色一律使用 §5.2 列出的 CSS token，不得为 rig 单独引入新色值；六主题切换时 rig 无需任何 JS 逻辑改动，靠 CSS 变量继承自动生效。
6. 声带振动、气流指示的动画必须包裹在 `@media (prefers-reduced-motion: no-preference)`，`reduce` 模式下声带振动降级为纯色块状态切换（不做波纹动画），气流线降级为静态显示（不做扩散动画），完全对齐设计系统文档已定义的降级规则，不得跳过。
7. `/ŋ/` 的气流出口图层（鼻部）与其余音位气流出口图层（唇部）在 SVG 结构上必须是两组独立的可见性开关，不得用同一组图层做位移复用——两者形状与锚点位置本身不同，强行复用会导致动画路径不自然。
8. `MinimalPairComparison` 组件的双语音播放严格走 `AudioService` 单通道打断规则，不得为"同时播放对比"功能引入并行播放两路音频的例外逻辑（哪怕只是先后错开 400ms，也要保证任意时刻只有一路 voice 通道在响，避免打破 AGENTS.md 音频红线的一致性）。
9. M2 完成后必须实测：男声/女声、正常速/慢速四种音频变体下，本文档定义的 4 关键帧插值观感是否明显漂移（尤其 `/θ/` 摩擦音的气流线循环节奏、`/ŋ/` 软腭开合与鼻音起始点的感知对齐）。若发现明显错位，按架构文档预留的 `perVariantOverrides` 字段做局部微调，不得推翻本文档已定的关键帧数量与整体机制。
